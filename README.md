# 美食物语 · Web3D 交互厨房

第一人称 Web3D 美食制作网页：在厨房里从冰箱取食材、切配、下锅烹饪，用空盘子装盘后端上餐桌品尝，吃完的脏盘子拿去水槽洗净还能继续用。没有倒计时、不会失败，做菜的同时累积经验、解锁新菜谱、给每道菜点亮星星。所有 3D 内容都由代码实时生成，不依赖任何外部模型文件。

## 运行

```bash
npm install
npm run dev      # 本地开发，默认 http://localhost:5173
npm run build    # 生产构建，输出到 dist/
npm run preview  # 预览构建结果
```

## 操作方式

| 操作 | 桌面端 | 移动端 |
| --- | --- | --- |
| 转动视角 | 移动鼠标（指针被锁进画面，没有鼠标指针） | 单指滑动 |
| 移动位置 | W A S D 或方向键 | 双指拖动 |
| 切换物品栏 | 数字键 1-6（也可以直接点底部的格子） | 点底部的格子 |
| 交互 | 准星对准目标后点击左键 | 准星对准目标后轻点 |
| 把手上的东西放回原处 | Q | 点一下已经选中的格子 |
| 下蹲 / 站起 | 按 Ctrl（按一下切换，再按一次站起） | — |
| 图鉴 / 菜单 | E / M | 右上角按钮 |

进入厨房后鼠标会被锁定在画面里，像第一人称游戏那样移动鼠标就直接转视角，屏幕上没有鼠标指针；按 Esc 释放鼠标，再点一下画面就能重新锁定。滚轮与右键不再参与任何操作，右上角喇叭按钮可以开关音效。

## 玩法流程

1. 8 种食材（番茄、鸡蛋、土豆、胡萝卜、卷心菜、蘑菇、牛肉、三文鱼）全部存放在冰箱里，每种食材占货架上一块自己的区域、区内按规则网格整整齐齐排满：卷心菜 4、土豆 9、番茄 20、鸡蛋 25、胡萝卜 10、蘑菇 20、牛排 4、三文鱼 6，合计 98 件，四层货架都塞满，不用把前面的挪开就能够到；拿一件这一堆就少一件，补货按堆的大小自适应（每 0.7–1.7 秒补回一件，整堆补满都在 15 秒上下）。准星对准冰箱门点击可以开关门（门轴在左侧、朝人这一侧向外打开），门开了才能拿取里面的食材。
2. 拿到的食材进入底部物品栏（和《我的世界》一样是 6 个格子），数字键 1-6 切换、也可以直接点格子。**所有操作都作用在"手上"的那一格**：格子里是食材就去切菜、下锅，是空盘就去装盘，是脏盘就去水槽。按 Q 把手上的东西放回原处，食材回冰箱、盘子回盘堆。手上显示的永远是这一格里的实物模型：食材就是对应的食材，切碎后变成一小撮碎块，空盘、脏盘和装好盘的料理各有各的样子。
3. 选中要切的食材，走到房间正中央的中岛切菜板前**连点 3 下**把它切碎：每一下刀都会落下、砧板掉出对应颜色的碎屑，第 3 下完成后这一格就变成切好的食材。切配进度按格子记录，切一半换走再换回来不会白切。
4. 选中切好的食材点击灶台，食材会一个个从手边划弧飞进锅里累积；锅里凑齐一道菜谱就自动开火，灶眼窜起火苗、锅身跟着震动翻炒，中段颠一次锅，约 2 秒后出锅——**做好的菜留在锅里**，锅底留一点小火保温。搭错了也不亏，空手点灶台可以把锅里的食材原样捞回物品栏重新搭配；没切碎的食材、尚未解锁的菜谱都会给出提示。
5. 灶台和水池中间的台面上放着一摞盘子（初始 5 个），正好在切菜、下锅、装盘这条动线上。先用数字键切到一个空格子（手上是空的），点盘堆就能拿一个干净盘子；端着盘子对准锅里的菜点击即可装盘，出锅 28 秒内装盘算「趁热」，额外给经验。
6. 端着装好盘的料理对准窗户对面墙角的餐桌点击，盘子会划一道弧线落到餐桌空位上；再对准桌上的料理点击，进入品尝动作。
7. 吃完盘子变脏：切到空格子点击桌上的脏盘子把它拿起来，对准水槽点击冲洗（水槽里会冒泡沫），洗好的盘子回到手上，可以再次装盘或放回盘堆。
8. 柜子、中岛、冰箱和餐桌都带碰撞箱，走不进家具里面，也跳不上桌面。房间左后方（和窗户所在墙面相邻的那面墙）有一扇门，是厨房的出口。
9. 厨房左墙挂着「今日菜单」看板，做完一道就在看板上打勾并拿到 22 点经验；三道**全部清空**会额外给 30 点经验，并立刻把看板换成下一天的新菜单（看板右上角与 HUD 都会显示「第 N 天」），接着做就行，不用等现实时间到第二天。菜单本身仍按真实日期换新，跨天回来也会自动刷新。

除鸡蛋外，其余 7 种食材都需要先在切菜板上切碎才能下锅。

| 系统 | 说明 |
| --- | --- |
| 经验 | 出餐 +12、首次做某道菜 +8、趁热上桌 +6、品尝 +10、洗盘子 +4、完成今日菜单 +22、菜单全清再 +30 |
| 等级 | Lv.1 起，Lv.2/3/4/5 依次解锁土豆浓汤、蘑菇煎牛肉、田园炖菜、香煎三文鱼配土豆，升级会弹出「LEVEL UP」卡片 |
| 星级 | 每道菜记录最高 3 星：出锅 1 星、趁热装盘 2 星、趁热装盘并端上餐桌吃完 3 星 |
| 连击 | 连续趁热上桌会累积连击，连击越高单次经验越多；凉了只是连击归零，不会扣任何东西 |
| 今日菜单 | 每次随机 3 道已解锁的菜（不足 3 道时按实际数量），完成打勾，全清 +30 经验并立即刷新出「下一天」的新菜单 |

## 技术要点

- **纯代码建模**：全部几何体由 `BoxGeometry`、`CylinderGeometry`、`SphereGeometry`、`OctahedronGeometry`、`ConeGeometry` 等基本体拼装，低多边形平面着色风格，无任何外部模型或贴图文件。
- **盘子是「车」出来的**：盘身不是几个圆柱叠起来，而是把一条剖面线（圈足 → 盘底 → 盘沿外壁 → 盘沿顶面 → 盘沿内坡 → 盘心凹面）交给 `LatheGeometry` 旋转成形，盘沿围一圈、盘心凹下去，装好的菜落在盘心里而不是浮在盘面上；盘堆复用同一条剖面按 1.6 厘米间距嵌套，并把整摞合并成两个网格。盘子按真实尺寸重做过一次：直径从 34cm 的大餐盘收到 **27cm**（盘沿高 2.4cm、盘心 1.56cm），食材、碗、菜品都是真实尺寸之后，这里是最后一个"超规格"的物件。
- **砧板碎屑按食材现切现做**：以前是 5 个固定绿方块、只按食材换颜色，切胡萝卜也掉方块；现在 `playChop()` 用和手持切碎态同一个 `createIngredientPiece()` 现场生成——切胡萝卜掉圆片、切卷心菜掉细丝、切番茄掉楔块、切土豆掉丁，掉完 2.7 秒自动收走。
- **脚步声**：`audio.js` 新增 `sfx.step()`（一段带低频闷响的短噪声），按走过的距离触发——站着 0.72m 一步、蹲着 1.05m 一步且音量更轻，左右脚用 ±12% 的音高差区分（实测走 2 秒：站着 7 步、蹲着 2 步）。此前 18 种音效里唯独走路是无声的。
- **窗外有景**：窗户玻璃改成半透明（`opacity 0.32`），后面贴一张程序化 CanvasTexture（天空渐变 + 太阳 + 三层远山），房间本身没在墙上开洞，所以这块板就充当"窗外"；此前那块玻璃是不透明发光面，窗外什么都没有。
- **实时光效与音效**：`audio.js` 用 `OscillatorNode` + 白噪声 `AudioBuffer` 现场合成全部音效（零音频资源）；`fx.js` 用共享几何体加逐帧积分的粒子系统做碎屑、蒸汽、星光与光环。
- **灶台演出**：灶台上一口真锅，火焰由一圈锥体拼成、缩放基准落在灶面上，点火时从无到有长起来，火光用一盏不带阴影的 `PointLight` 跟着闪；下锅时食材逐个从手边抛物线飞进锅里，落锅有火花、蒸汽与锅身震动，中段 `颠锅` 把锅铲起再落回，出锅后锅留一点小火保温，装盘走人后自动熄火。
- **补间系统**：`tween.js` 提供 `easeOutCubic` 缓动与补间队列（含二次贝塞尔抛物线），所有手感动画（手持物抬手、盘子划弧上桌、脏盘转身、盘堆回弹）都由它驱动，不引入任何动画库。
- **世界里飘字**：交互奖励用世界坐标 `Vector3.project()` 投影到屏幕，再由 DOM 元素做上浮淡出，兼顾了 3D 定位与文字清晰度。
- **动作进度不挡视野**：品尝、洗盘子从全屏弹窗改成准星下方的世界内小进度条，动作期间仍可自由走动与转头。
- **程序化贴图**：今日菜单看板用 `CanvasTexture` 实时重绘（含标题、菜名、勾选状态与完成计数），状态变化时按需刷新。
- **第一人称操作**：桌面端用 Pointer Lock 把鼠标锁进画面（没有鼠标指针），只用 `movementX/Y` 做相对转视角，俯仰限制在 ±77°；视角控制与渲染循环解耦，解锁时（Esc）弹出「点击画面继续下厨」的提示。指针锁定连续失败 3 次才降级成自由指针，避免一次瞬时失败就永久退化。准星只有一个中心实心圆点，对准可交互目标时放大变色。
- **家具碰撞**：冰箱门扇另有一块随开门角度实时重算的 AABB，门在转动过程中会把人顶开，不会出现穿门而过或卡在门板里；家具在 `kitchen.js` / `table.js` 里以 AABB 形式声明，移动后按"最短推出"把玩家挤出去（前进与横移合并成一次求解，贴着拐角走不会被同一帧往两个方向推）；推出候选点会被房间边界过滤，贴着墙的柜台不会把玩家顶到墙外。冰箱整体离墙 22 厘米、底部补了黑色踢脚、顶板与侧板齐平，投影不会全被夹在墙缝里。
- **房间按真厨房收紧**：原来是 8 × 8m、层高 3.2m（可活动区 7.2m 见方，走道两米多宽，像餐厅大堂）。现在 `ROOM` 常量把房间收到 **6.2 × 6.4m、层高 2.75m**，走道收到 0.9–1.6m：靠墙的两条长台面、冰箱、餐桌、后门、窗与绿植都用 `组.position` 整体内推（内部坐标不动，避免逐个改上百个硬编码坐标），天花板、踢脚线、烟道、吊灯吊杆跟着层高收短，碰撞 AABB、食材落位、盘堆位置、菜单看板与出生点一并按同样的位移更新——出生点从 (-0.9, 1.9) 挪到 (-0.9, 1.2)，避免一开局就卡在餐桌椅子里。
- **收房后修掉的三处穿模 / 挡路**：① 餐桌两端各有一把椅子，房间收窄后右侧椅背离 +x 墙只剩 1cm（看上去像穿墙），桌子整体从 x1.4 挪到 **x1.0、z2.7**，实测桌椅占地 x[-0.64, 2.64]、离 +x 墙 41cm；② 水槽原来贴着左后墙角够不到，整段柜体右移 **50cm**——这里一开始只挪了水盆和它旁边的两条台面条，台面开孔与柜体分段还留在原位，结果水盆一半钻到台面下面、旁边留了个洞；现在把整条 -z 台面按新的三段重排（左角柜 A / 水槽柜 B / 主柜 C），**三段共用边界**（`A.max = B.min`、`B.max = C.min`，柜体正面不留缝、也不互相穿插），台面开口与柜体宽度由同一组边界算出，盘堆跟着从 x-1.62 让到 x-1.32；③ 后门原来嵌在墙角里、门框扎进 -x 墙，且被墙角的绿植挡住，整扇门右移 **1.0m**（花盆位置不变），现在门框离墙 70cm、绿植在门侧不再挡门。三段重排后烤箱（占 x −1.15 ~ 0.75）与柜门还有一次重叠，柜门已重新按「烤箱左侧 1 扇 + 右侧 3 扇」摆放，不再压在烤箱立面上。
- **下蹲**：按 Ctrl 切换蹲姿，视点高度 `EYE_HEIGHT 1.62m → CROUCH_HEIGHT 0.95m` 按 `CROUCH_LERP 9` 平滑过渡（不会瞬移），移动速度乘 `CROUCH_SPEED 0.45`；实测蹲着按住 W 一秒走 0.59m、站着走 1.26m。做成"按一下切换"而不是"按住"，是因为浏览器里按住 Ctrl 再按 W 会触发 Ctrl+W 关掉标签页——单按 Ctrl 不会。碰撞半径不变（家具的 AABB 是二维的，蹲下也钻不过柜台），下蹲只影响视点高度与速度，交互射线跟着视点一起降低。
- **射线交互**：中央准星发射 `Raycaster`，沿父级回溯命中可交互对象并附带距离限制与发光高亮；每个可交互对象可以声明优先级，盘子与料理这类小物件优先于桌面、台面等大面积命中板。
- **单光源照明**：厨房只有吊灯里的一盏 `PointLight` 投射阴影（吊灯挂在房间正中央、中岛切菜台正上方），配合 `shadow.intensity` 调低阴影浓度与极弱环境补光，消灭满屋乱影与纯黑死角；灯罩不参与投影，避免天花板被灯罩整片遮黑。
- **薄壁物体的阴影偏移**：冰箱门只有 6 厘米厚，`normalBias` 一旦偏大，沿法线偏移的采样点就会穿过门板，在墙上留下一块块硬边亮斑（开门、关门都能看到，开门时最明显）。现在按最薄的那块板来定量：`normalBias` 0.012、`bias` -0.0012，墙上的亮斑消失，同时没有引入阴影自遮挡。
- **阴影按需刷新 + 演出期节流**：点光源阴影是六面立方体贴图，场景里又几乎每个物体都参与投影，每帧全量重算会在静态画面上白烧掉约 20% 的帧时间（绘制调用 427 → 127）。因此关掉 `shadowMap.autoUpdate`，只在世界真的发生变化时（食材与道具增减、冰箱门转动、脏盘与水泡状态变化）置一次 `needsUpdate`，站着不动或单纯走路完全不重算阴影；切菜、烹饪、开门这类演出期间阴影最多每 100 毫秒刷一次（`SHADOW_INTERVAL`），把原来每秒 60 次的六面重算压到 10 次以内，消除演出时周期性掉帧，软边阴影的观感没有变化。
- **自适应分辨率**：`devicePixelRatio` 上限从 2 收到 1.5，`dpr` 大于 1.25 时关闭 MSAA（高分辨率下 4x 采样的填充开销远大于它带来的收益）。运行时按帧间隔自动升降渲染缩放（0.55–1.0）：先把观测到的最小帧间隔当作显示器刷新间隔（60/120/144Hz 都能自适应，不写死 60），平均帧时间连续 20 帧超过刷新间隔 1.3 倍就降一档，回到刷新间隔附近再缓慢升回来；启动后有 60 帧预热期，切走标签页再回来也不会被突然的超长帧误判成掉帧而白降画质。
- **粒子与飘字复用**：特效粒子改成对象池（`MAX_PARTICLES` 96），碎屑、蒸汽、星光、光环全部复用共享几何体与材质，超出上限时回收最老的一颗。之前连续触发特效时绘制调用会从 127 飙到 1000 以上（每颗粒子一次绘制调用），现在最坏情况也只有约 140。世界里飘出的文字标签同样建池并封顶 12 条，提示条封顶 4 条，避免瞬间生成几十个 DOM 节点、每个节点每帧还写两次行内样式。
- **不阻塞合成的界面更新**：动作进度条从逐帧改 `width` 换成 `transform: scaleX()`（只走合成，不触发布局）；今日菜单列表按内容做键比对，内容没变就整段跳过 DOM 重建；浮字层与提示层加上 `contain`，把样式重算限制在各自的小盒子里。
- **界面可读性与窄屏适配**：HUD 正文统一到 13px，叠在 3D 画面上的半透明底（准星提示、操作提示、物品栏、今日菜单、手上信息）不透明度提到 0.68–0.94，19 处文字实测对比度都在 4.5:1 以上（WCAG AA 小字标准，未解锁的图鉴卡片也从「整卡 60% 透明」改为受控的浅灰底 + 加深文字）；**开始界面只留标题、副标题与三个按钮，原来的操作说明列表已整段删除**（操作说明保留在游戏内左上角那张竖排卡片里，不占开屏版面）；窄屏（≤680px）顶栏折成「状态一行 + 按钮一行」，操作提示与今日菜单分左右两列，320×640 到 1920×1080 全部尺寸实测无溢出、无遮挡；飘字提示同时在屏上限 2 条，按键说明只保留在操作提示一处。
- **HUD 按视口高度分档避让**：动作进度条原本固定在准星下方 78px，窗口高度小于约 640px 时会压住「手上信息」、更矮时还会压住物品栏（1280×600 实测重叠 184×21px）。现在按 `max-height` 分档：≤720px 时手上信息与物品栏下移、进度条上移；≤620px 时物品栏收起流程提示、进度条改为贴着底部 HUD 摆放并让出「手上」一栏（手上拿着什么在物品栏选中格和手持模型上都能看到）；≤470/440/400/380px 再逐级收紧提示条与物品栏尺寸，360px 高以内的横屏窗口也不会压字。手上信息里的「盘堆 N」已删除，拿盘子时准星提示里仍会给出剩余数量。
- **左上两块信息改纵向**：信息块原本把主题标签、等级、三项数据、经验条挤在一行，现在拆成纵向三段（标签行 / 数据行 / 经验条通栏），经验条通栏撑满，一眼扫完不用横向找；它下面的操作说明条也从 578px 宽的横排长条改成 153px 宽的竖排卡片，**一种操作一行**（移动鼠标转视角 / W A S D 移动 / 左键交互 / 数字键 1-6 切换物品 / Q 放回 / E 图鉴 / M 菜单），触屏设备自动换成对应的手势版本（单指滑动转视角 / 双指拖动移动 / 点击交互 / 底部物品栏点一下即可切换）。因为信息块变高，操作提示从 76px 下移到 98px，飘字提示从 86px 挪到 142px——原先飘字和操作提示就在互相压字（实测重叠 114×27px），顺手一起修掉了。窄屏仍保持紧凑排布：等级、数据、经验条同行，按钮另起一行，操作说明条按宽度断点隐藏。
- **食材按真实尺寸建模 + 切碎形态分型**：8 种食材从「15–27cm 的大块」改成贴近真实的尺寸（番茄 6.8×7cm、鸡蛋 4.8×6.2cm、土豆 9.7cm、胡萝卜 21cm 平放、卷心菜 17cm、蘑菇 5.2cm、牛排 15.5×12.3×3cm、三文鱼排 14.5×7.8×3.2cm），冰箱货架原本 19cm 的前后间距下牛肉和三文鱼已经贴在一起，现在留出余量；土豆从棱角分明的正二十面体改成扁椭圆 + 表面取点算出的 5 个芽眼和 2 处小凸起；牛排的脂肪挪到侧边、表面改成浅色大理石纹；三文鱼用三棱柱（`CylinderGeometry` 3 段）做出「一侧厚一侧薄」的鱼排剪影并保留鱼皮；胡萝卜改成锥体平放 + 三片锥形叶。切碎后的形态不再共用一堆方块，按食材分成四种：圆片（胡萝卜、蘑菇）、楔块（番茄）、细丝（卷心菜）、丁（土豆、牛肉、三文鱼、鸡蛋），每种约 5–8cm 一小撮。因为模型改成真实尺寸，手上和锅里的缩放系数同步调整（手上按模型长度归一化到 12cm、限幅 0.75–1.6 倍，锅里下锅 1.0 倍、落定 0.85 倍），并修掉了「切好的食材下锅后又变回整块」的问题。
- **菜品沿用切好的形状 + 换成真碗**：六道菜的成品不再各写一套「整块多面体」，而是复用玩家切出来的那些件——番茄炒蛋是番茄楔块 + 滑蛋块、时蔬沙拉是碗里拌卷心菜丝/胡萝卜片/番茄块、蘑菇煎牛肉直接用煎好的牛排（`createIngredientModel('beef')`）配五片蘑菇片、土豆浓汤是碗里奶白汤面 + 几粒小料、田园炖菜是清汤里半露的土豆丁/蘑菇片/卷心菜丝、香煎三文鱼配土豆是楔形鱼排 + 两球土豆泥，六道菜的块料尺寸都落在 1.3–4cm。原来沙拉/浓汤/炖菜共用一只 `cylinder(0.15, 0.085, 0.1)` 的圆锥台（口径 30cm、比盘子还宽，汤面藏在碗口以内根本看不见），现在和盘子一样用 `LatheGeometry` 车一只真碗：口径 18cm、深 8cm、带圈足，汤面放在口沿下方 1.8cm，正常吃饭视角就能看到碗里。顺手修掉了「香煎三文鱼配土豆」的坐标笔误——土豆泥球的 `z` 写成了 0.35/−0.30（35cm/30cm），原来每次上桌都有一颗球飘在盘子外面 30cm。装盘/下锅的位置改由 `restOn(holder, floorY)` 统一处理（盘心 0.0196、锅底 0），菜品在锅里也不再浮空。
- **锅终于有内胆了**：灶台上的两口锅原本是「一段实心圆柱 + 浮在顶面上 1mm 的一块圆盘」，从任何角度看都是一个黑圆盘盖在锅上，没有内壁也没有锅底。现在用 `palette.lathe()` 车出完整剖面（锅底 → 外壁 → 收口锅沿 → 内壁 → 内底），锅内径 27.6cm、深 4.6cm，内底用稍浅的 `PAN_INNER` 材质，俯视能看到内壁和锅底的明暗分界。连带把落位基准从旧的「顶面」改成真正的锅底（`foodSpotLeft/Right.y = 1.04 + PAN_FLOOR_Y`），锅里食材的下锅高度从固定 +5.5cm 收到 +0.4cm、特效原点从 +12cm 收到 +7cm，食材和出锅的菜现在都贴在内底上；锅柄也从「伸进锅内 5cm」挪到外壁接出。
- **冰箱里每种食材是一堆，按区域整齐排满**：单件食材先用 `palette.bakeModel()` 按材质烘成「每种材质一份合并几何体」，再用 `InstancedMesh` 按 `cols × rows` 的规则网格复制成堆（奇数行错半格、朝向统一），每种食材占货架上一块独立区域——卷心菜 4、土豆 9、番茄 20、鸡蛋 25、胡萝卜 10、蘑菇 20、牛排 4、三文鱼 6，合计 98 件，而每堆只占 2–3 个网格。拿取时只改实例数量 `count`、补货时加回来，几何体一次建好，不重建也不增加绘制调用：冰箱从 8 件变 98 件后，静止画面绘制调用仍是 110（三角面约 2.6 万，帧率不受影响）。补货间隔按堆的大小自适应（`max(700, 7000 / 容量)` 毫秒一件，整堆补满约 15 秒），准星提示会显示「还剩 N 份」，按 Q 放回手上食材时也会先补到没满的那一堆。
- **笔记本独显偏好**：`WebGLRenderer` 显式声明 `powerPreference: 'high-performance'`，双显卡笔记本上避免被浏览器分到核显上跑。
- **指针锁与按键的健壮性**：`requestPointerLock` 失败不再累积到 3 次就永久禁用（旧逻辑会让鼠标视角再也锁不上、只能拖拽），改成 1.4 秒冷却后重试；窗口失焦或标签页切走时清空按键集合，避免 `keyup` 丢失导致角色一直往前走；已经成功锁定过的情况下，按 Esc 解锁后的第一次点击只用于重新锁定，不再顺手触发一次交互。
- **存档与迁移**：图鉴数据写入 `localStorage`（schema v2），旧版本的纯图鉴存档会被自动折算成经验并保留已解锁菜谱，不会因为升级而清空进度；存档里的今日菜单会按当前菜谱表过滤一次，删掉或改过名字的旧菜谱 id 不会再让界面报错。
- **每日菜单抽样的精度陷阱（已修）**：抽样用线性同余随机数，原式 `seed = (seed * 1103515245 + 12345) % 2147483648` 在 seed 接近 2³¹ 时，乘积约 2.4×10¹⁸，超出 JS 双精度能精确表示整数的 2⁵³，低位被抹成 0，结果恒为 512 的倍数。于是当"已解锁料理数"是 4（3 级）、8、16 这类 2 的幂时，`seed % pool.length` 恒等于 0，只能抽到同一个下标，`while (picked.length < 3 && used.size < pool.length)` 两个条件都永远成立 —— 主线程死循环，页面直接变成"没有响应"。这条路径只在需要**重掷菜单**时走到，也就是**跨天首次打开**，且解锁数恰好是 2 的幂，所以此前一直没被发现。现在改用 `Math.imul` 做精确 32 位乘法、给循环加尝试上限，并在抽不满 3 道时按顺序补齐。
- **启动失败不再是一片黑**：`index.html` 里注册了启动看门狗与错误捕获，初始化抛异常或 15 秒还没起来时，会在页面顶部显示具体原因（而不是留一个全黑、点不动的画面）；WebGL 上下文丢失时也会给出提示。渲染器创建失败会退回关掉 MSAA 再试一次。
- **性能设定**：像素比上限 1.5（可自适应降到 0.55）、阴影贴图 1024、`PCFShadowMap`（three 0.185 起 `PCFSoftShadowMap` 已废弃，用它会每帧打印告警并自动降级）、`ACESFilmic` 色调映射；静止时单帧绘制调用约 127 次、特效拉满时约 140 次，三角面数千，堆占用稳定在 25MB 上下且不随游玩时长增长。单帧时间步长上限 0.1 秒，切走标签页再回来不会瞬移。

## 开发调试

遇到"页面没有响应"时，先按 Ctrl+Shift+R 强制刷新；如果还是黑屏，注意页面顶部是否出现了红字提示，那行文字就是原因。同一个游戏同时开多个标签页会争抢显存，建议只留一个。

开发模式下可以直接在控制台调用 `window.__game.perf()` 查看实时帧率、平均帧时间、渲染缩放、像素比、绘制调用与堆占用，用来确认是否稳在 60 帧。`window.__game` 暴露了 `camera`、`renderer`、`scene`、`kitchen`、`table`、`menuBoard`、`picker`、`fx`、`items`、`spots`、`state`、`fridge`、`chopStation` 与若干流程函数（含 `setHand`、`toggleFridge`、`takeIngredient`、`doChop`、`doCook`、`usePlateStack`、`useSink`、`useCounter`、`useTable`、`useItem`），另外还有自动化测试用的 `selectSlot`、`dropSelected`、`pot`、`cookPhase`、`isFridgeOpen` 与 `teleport(x, z, yaw, pitch)`，便于在控制台核对状态或做端到端测试；该挂在 `import.meta.env.DEV` 分支内，生产构建不会包含。
